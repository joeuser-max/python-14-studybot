# ClassPulse V2｜排程板、AI 教練與群組訓練的最小可執行架構

## 1. 問題的第一性原理

原 UI 把『任務新增／手動指定』與『全體任務重新排程』耦合；使用者只想固定一件事時，其餘任務也被改動。新的核心規則：**所有可能覆寫安排的操作都必須是使用者的明確動作**。

```text
建立任務 → 待排卡片
          ├── 橫向改長度 → 只更新該任務的預估時間
          ├── 拖到 7 日板 → 驗證 → 僅排入該任務
          └── 一鍵填滿 → Deadline / 長工時優先 → 只排尚未安排的任務

外部 .ics → 驗證與去重 → 本機事件（衝突判定）→ 確認覆寫 → 合併匯出 .ics
LINE 回報 → 對應任務進度 → 更新總覽；已用新版規劃板時不重排其他任務
匿名訓練模板 → 選擇參考節奏 → 明確 API 同意 → Gemini 候選建議
                                                ↓
                         本地排程驗證 → 使用者逐項確認 → 拖排引擎
```

## 2. 固定 7×16 規劃單位

- 時間範圍：臺北時間今天 T+0 至 T+6，包含週末；過去的日期不顯示，今天已經過去的節次禁用。
- 節次映射：`1=08`、`2=09`、`3=10`、`4=11`、`Z=12`、`5=13`、`6=14`、`7=15`、`8=16`、`9=17`、`A=18`、`B=19`、`C=20`、`D=21`、`E=22`、`F=23`。
- 學校上課節通常 50 分鐘，ClassPulse 每格以整點至下個整點作**規劃與休息緩衝**；E/F 是應用程式延伸的夜間格。
- `week_planner.py` 是唯一的手動排入／一鍵填滿判定入口；`week_board.py` 只傳送操作事件，不直接編寫 JSON。

## 3. 資料契約

| 檔案／模組 | 欄位／操作 |
|---|---|
| `tasks.json` | `task_id`, `user_id`, `deadline`, `estimated_minutes`, `status` |
| `plan.json` | `task_id`, `availability_id`, `source` (`manual/auto`), `scheduled_start`, `scheduled_minutes` |
| `availability.json` | 使用 `board_<task_id>` 合成一筆板上時段，保留舊排程器相容性 |
| `external_events.json` | `id`, `start`, `end`, `title`, `source_uid`, `source_name`, `edited_in_classpulse` |
| `week_board.py` | 動作 `drop`, `resize`, `unplace`, `fill`, `external_edit`，後端再次驗證所有欄位 |
| `study_coach.py` | HTTP 模型輸出 JSON：`summary` + `actions[]`，其中每項有 `task_id/date/period/blocks/reason` |
| `peer_exchange.py` | 本機自願交換匿名習慣：每週安排數、偏好節次、最長時數、**未驗證**的彙總指標 |

## 4. AI 的可驗證責任

AI 的比較不是『誰讀書時數多』。它將一個參考節奏（例如每週 4 次、每次 2 節）透過學生自己的固定課與外部行程，轉成候選時間槽。**模型不擁有資料庫寫入權限**；回傳的 task ID、日期、節次、時長先經 `week_planner._candidate` 檢查，若有衝突則拒絕；再由使用者明確按確認。

Gemini 2.5 Flash-Lite 使用可設定的 HTTP API，能在無金鑰時運行核心 UI；Mock 測試只證明請求／解析／驗證契約，不冒充真實模型回應。免費層的額度及資料使用政策請以 Google 官方最新條款為準；操作前明確顯示傳送資料類型與同意控制。

## 5. 如何公平評估而不是做出虛假的 Elo

1. **任務完成率**：完成任務數／總任務數；純粹自我回報，很容易灌水。
2. **LINE 回報完成率**：帶 `study_session_checkin` 的到期推送與回覆連結；提供第二層事件證據，但回覆『完成』仍未驗證實際學會。
3. **Focus XP**：自填完成 +20、具 LINE 完成回報再 +10，用來促進連續使用。**不是 Elo、正式排名或認知能力測量**。

跨使用者的可比較單位未來應以**時間負荷校正後的已確認進度**、連續性、缺漏值和資料來源可信度評價，而非單純用每日總時數排榜。實際版本還需身分驗證、授權同意、避免多帳號刷分與個資保護。現版只提供匿名節奏檔交換，不保存實名同學名單或發布校內排行榜。

## 6. 明確不保證的能力

- `.ics` 編輯是本機副本更新與匯出，**不**透過 Google/Outlook API 直接修改外部帳號。
- 單機 JSON 鎖不是跨多檔案交易；高併發應改成資料庫＋唯一索引、樂觀鎖。
- Streamlit HTTP 啟動與 pytest 成功**不等於**所有瀏覽器拖放、手機觸控、真實 LINE 或 Gemini 配額已驗收。
- 現階段並未蒐集同校人的真實參考效率，也無法宣稱任何排名。

## 7. 回歸測試

以 `python -m pytest -q` 驗證手動不影響其他待排、auto 僅填空、衝突和期限、七日滾動、ICS 去重與覆寫確認、匿名模板無個資、Gemini 回傳非法任務拒絕，以及新版 LINE 不意外重排。
