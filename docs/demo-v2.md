# ClassPulse V2｜三分鐘展示腳本

> 目的：展示「學生手動掌控排程 → 自動補空格 → 外部行事曆 → AI 教練協助調整」的最短可執行閉環。**全程不需要外部 API 金鑰或 LINE Token**；任何模型模擬都有明確的 Mock 標示，不冒充真實推論。

## 現場前確認（不列入三分鐘）

1. 在正確 Repository 的根目錄執行 `python -m pip install -r requirements.txt`、`python -m pytest -q`。
2. 執行 `python -m streamlit run app.py`。在首頁上方開啟 **「展示模式（使用獨立的範例資料）」**，按 **「重設展示資料」**。此操作只修改獨立的展示 JSON，不會覆寫正式資料。
3. 確認「七日規劃板」左側有 **至少兩項待排任務**。若沒有，可能是先前 Demo 的資料已改動，請重新按「重設展示資料」。
4. 備妥 `examples/demo_external_calendar.ics`，以及開啟 GitHub PR 頁面作為程式架構證據。

## 現場三分鐘

| 時間 | 操作 | 要證明的事情 |
|---|---|---|
| 0:00–0:35 | 顯示 7 天 × 16 節；拉動待排卡右側把手，手動把一項任務放進任一未被佔用的格子 | 時長改變由卡片控制，手動只影響**一項**任務，其他待排不會自行跑進日曆 |
| 0:35–0:55 | 點「一鍵填滿剩餘任務」，檢視剛才手排仍在原時段 | 規則式排程僅填剩餘任務，不覆蓋既有手排、固定課程與外部事件 |
| 0:55–1:30 | 展開 ICS 匯入，選擇 `examples/demo_external_calendar.ics`，預覽後確認匯入，點擊黃色外部事件 | 外部行事曆可匯入、顯示及匯出；修改本機事件會先彈窗確認覆寫，**不假裝寫回 Google/Outlook** |
| 1:30–2:05 | 進「總覽與回饋」顯示完成率、LINE 回報率、Focus XP，匯出匿名訓練模板 | 遊戲化鼓勵參與，但自填紀錄不代表學力，不宣稱虛構的校內排名 |
| 2:05–2:45 | 選一種訓練模板，在展示模式點「體驗教練產生候選方案（Mock）」；顯示候選時間並按確認 | AI API 的**資料契約和人工確認入口**可操作；模型建議需通過本地排程驗證，Mock 不使用網路 |
| 2:45–3:00 | 指向 `study_coach.py` 的 Gemini HTTP 入口與 GitHub CI；結尾強調 AI 不能直接覆寫行事曆 | 真的有可設定的 Model API，但沒金鑰時仍能展示完整骨架 |

## 區分可驗證與尚未完成

- **已測：**根目錄 Python 測試；GitHub Actions 的 Chromium 拖放、七日節次與一鍵填滿互動測試；ICS 匯入、重複事件及衝突提醒；API Request／Response 的 Mock 契約。
- **未驗證：**真實 Gemini API 配額／可用性、LINE 官方帳號真實送達、多人登入與跨裝置同步、校內排名或真實同儕訓練效益。
- **同儕功能現況：**自願交換匿名粗粒度 JSON「訓練節奏」，由模型將它對應到自己的時間表；不是同校同儕資料庫或防作弊計分系統。
- **評量邏輯：**任務完成率、LINE 回報完成率、Focus XP 是使用行為回饋；受自我回報限制，不能直接比較不同學生的學力。日後要建立可信群組 benchmark，應使用可稽核事件、採樣期間、有效任務定義及使用者明確授權。

## Demo 出錯的備案

- 先檢查 `python -m pytest -q`；若瀏覽器拖放不順，使用 **先點卡片 → 再點空白格** 的同等操作。
- 若 ICS 事件已存在，可勾選覆寫**本機副本**，再匯入相同檔案；如與讀書安排衝突，先看衝突警告並確認。
- 如 Gemini 金鑰無效，使用展示模式的 **Mock 教練**，不聲稱真實 API 已成功連線。
- 如 LINE 尚未設定，使用頁面的模擬提醒／筆記回饋，說明 Webhook 及簽章在原始碼中，但不宣稱已送出真實 LINE 訊息。
